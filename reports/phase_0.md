## 7. Issues needing your decision (nothing below was changed on my own)

1. **Eagle `job_id` not unique** (contract §3.1 says unique). 6,751 ids repeat
   (371,160 rows, up to 1,001 rows per id);
   105,510 of those rows are exact copies of another row.
   Rows on a repeated id share user and name, so they look like Slurm array tasks without the
   array index — UNKNOWN — needs check (not documented in sources we hold).
   Options: (a) add a contract column `row_id` (int64, position in the raw file) as the unique
   key and keep `job_id` as given — **recommended**, keeps D8; (b) drop exact copies in a
   per-phase filter (Phase 1 would then differ from F5 counts); (c) leave as is.
   Phase 1 does not join on `job_id`, but Layer 1 score tables (§3.1) are keyed by it.
2. **PM100 row count vs F7**: file has 231,238 rows; F7 (Zenodo page) says 231,116.
   File MD5 equals the published one, so this is the published file. F7 needs correcting or an
   explanation (e.g. the page counts a filtered subset) — UNKNOWN — needs check.
3. **`mem_req` units** for both datasets: UNKNOWN — needs check (not stated in F2/F8).
